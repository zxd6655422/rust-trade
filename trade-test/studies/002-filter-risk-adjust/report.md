## 1. 目的

研究 001 的「BNB 不建议过滤」结论**只比较了总收益**，这是片面的。

用户的观点：**过滤器的核心价值是「抗灾/稳定」——避免未来某天出现 BTC/ETH/SOL 那样的反复止损暴跌**。即使过滤让总收益略降，只要收益更稳、回撤更小，风险调整后就是划算的。

本研究用风险指标（最大回撤、最差年份、亏损年份数、年度波动率、类Sharpe）重新对比「基线 vs 过滤后」，验证上述观点。

## 2. 数据与方法

- 数据：`src/feature_report/trade_features.json`（6 币种，最新代码生成）。
- 过滤：逐币种阈值（研究001），入场时 `realized_vol_48 >= 阈值` 跳过。
- 指标：总收益(简单/复利)、最大回撤(资金曲线)、最差年份(简单)、亏损年份数、年度收益波动率、类Sharpe(年度均值/年度波动率)。

## 4. 结论

1. **用户的观点成立，且比「只看总收益」更本质**：过滤对 **5 个币（BNB/BTC/ETH/SOL/HYPE）都大幅降低了最大回撤、消除了灾年、提高了类Sharpe**——这是过滤器的真正价值。

2. **BNB 结论修正（依然成立，且更强）**：研究 001 说「BNB 不建议过滤」是错的。最新代码下过滤后 BNB：
   - 最大回撤 **43.5% → 22.9%**（几乎腰斩）
   - 最差年份 **-10.4% → -7.2%**
   - 亏损年份 **3/7 → 1/7**
   - 类Sharpe **0.72 → 1.13**
   - 而且总收益反而也涨了（+89.0% → +187.7% 复利）
   - **结论：BNB 应该启用过滤**（前提是未来出现类似 BTC/ETH/SOL 的高波动灾年，过滤能兜底）。

3. **SUI 是唯一例外（依然成立）**：过滤后 SUI 总收益提升，但最差年份反而变差（-8.5%→-16.4%）、类Sharpe 略降（0.66→0.52）。原因是 SUI 的亏损不属于「高波动段」，vol 过滤没能覆盖。SUI 的过滤是「收益正、风险中性」，不是「收益正、风险也降」。

4. **ETH 的过滤效果较旧版减弱（本次重跑的新发现）**：取消趋势反转出场后，ETH 基线从 −35.6% 恶化到 −54.6%（ETH 是需要趋势反转出场来止损的币），过滤后收益也从旧版 +181.4% 降到 +95.8%，过滤后亏损年份从 3/10 升到 5/10。过滤仍能压住最大回撤（69.0%→35.3%），但「灾年消除」不如旧版彻底。

5. **为什么 walk-forward 与研究 002 结论表面冲突**：
   - walk-forward 问的是「阈值能否泛化、总收益是否提升」。
   - 本研究的风险指标问的是「过滤能否压住回撤和灾年」。
   - 对「用于抗灾的过滤器」来说，后者更重要。

## 5. 修正后的总体结论

> 高波动过滤的价值主要在**风险控制**：对 BTC/ETH/SOL/BNB/HYPE 都能把最大回撤砍掉约一半、消除灾年。
> 建议**6 个币种全部启用**逐币种阈值过滤；SUI 单独注意（它能提收益但压不住其非高波动型亏损）。

## 6. 局限

- 阈值为样本内确定，样本外仍需持续检验（研究001已做部分）。
- 未计手续费/滑点；过滤减少交易次数在真实成本下是加分项。
- HYPE/SUI 历史较短，结论置信度低。
- **口径提示**：当前 Python 基线「取消趋势反转出场」与生产 Rust `check_exit_conditions()` 并不完全一致——生产 `engine.rs` 仍保留了 `check_trend_reversal()`（MA288 与 MA488 交叉平仓）。若目标是回测严格对齐生产，趋势反转出场这一步应恢复，届时基线/过滤数字会再次变化（详见 `src/compare_reversal_exit.py`）。
